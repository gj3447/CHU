`./chu concept query distinction`에서 시작한다. 철학적 참이나 HSWM 실행 상태의 검증과 구별한다.

## 1. 대상, 표현, 구현

세 가지를 구분한다. (a) 우리가 말하는 인지능력체, (b) 그것을 설명하는 수학적/계산적
모델, (c) 모델의 일부를 실행하는 컴퓨터 시스템이다. 모델 속 기호의 존재는 물리적
대상의 존재 증명이 아니고, 실행 가능한 구현 하나가 개념의 가능한 사례를 모두 대표하지도 않는다.

하이퍼그래프는 CHU에서 **여러 대상의 역할 있는 관계를 표현하는 공통 문법**으로 삼는다.
다음은 구현에 연결하기 위한 AI의 최소 표현 제안이지, CHU가 되는 필요충분조건의 선언은 아니다.

`H = (V, E, type, participants)`에서 `participants(e)`는 `(역할, 대상)`의 유한 순서열이다.
한 대상의 여러 관계 참여와 같은 대상의 한 관계 내 여러 역할을 구분한다. 역할·순서·타입을
없애면 질의의 뜻이 달라질 수 있다. 단순 집합형 하이퍼엣지와 이 표현을 자동 동일시하지 않는다.

관계를 또 하나의 대상으로 참조할 수는 있다. 그 경우 관계의 참조 ID와 참여 관계를 명시한다.
이것을 곧바로 자기 자신을 포함하는 집합이나 `CHU : CHU` 같은 타입 공리로 옮기지 않는다.
집합론, 타입이론, 실행 DB는 각각 자기참조를 허용하는 조건이 다르다.

사용자의 “우리 우주 자체도 월드모델 CHU”는 [귀속된 철학적 관점](../canon/CHU_AND_CHU_OS.md)이다.
이 관점에서 탐구를 시작할 수 있지만, 물리 우주가 특정 유한 그래프와 동형인지,
인지·의식이 있는지, 내부 관찰자가 전체 우주를 완전히 예측할 수 있는지는 별도 질문이다.

## 2. 동일성은 비교 기준을 요구한다

| 비교 기준 | 무엇을 같다고 하는가 | 무엇까지 같다고 하지 않는가 |
|---|---|---|
| 내용 동일성 | 주어진 인코딩에서 바이트가 같음; OS는 CID로 주소화 | 뜻, 사건, 실행 주체, 정당한 권한 |
| 구조 동형 | 타입·역할·순서를 보존하는 명시적 대응이 있음 | 원본 바이트, 물리 대상, 수행 이력 |
| 관측 동등성 | 지정한 질의/관찰 집합에서 같은 답을 줌 | 모든 가능한 관찰에서 동등함 |
| 시간적 지속성 | 변화하는 사례를 어떤 연속성 기준으로 같은 대상으로 추적함 | 내용이 항상 같음, 분기한 복제본이 한 사건임 |

동형/동등성을 쓸 때는 대응 함수, 비교 범위, 검증 방법을 함께 적는다. “비슷하다”는
검색 결과만으로 같은 대상으로 병합하지 않는다. CHU_OS의 raw-byte CID는 첫 행의
공학적 선택이며 모든 인지능력체의 철학적 정체성을 SHA-256으로 정의하지 않는다.

예를 들어 본문은 같아도 두 사람이 각각 승인한 사건은 다르다. 같은 기억을 복사한 두
에이전트도 다음 입력과 실행 이력이 갈라질 수 있다. 두 사례가 철학적으로 같은 CHU인지의
판정은 아직 열려 있으며, OS는 이를 임의로 병합하지 않고 분기와 출처를 보존해야 한다.

## 3. 상태, 사건, 시간

상태 `S`는 선택한 범위의 표현이다. 사건은 단순 결과 상태와 구분해
`e = (발생 식별자, 이전 상태, 규칙/입력, 이후 상태, 출처)`로 기록하는 것을 제안한다.
가능한 전이는 관계 `S —e→ S′`이고, 실제로 발생했다고 기록된 전이와 구분한다.
전체 함수인 재작성 모델은 실패·거부·비결정성을 별도로 표현해야 한다.

`A → B → A`의 마지막 내용은 처음과 같을 수 있다. 그렇다고 중간 사건이 없었던 것은 아니다.
2026-10-09 [저장 실험](../research/storage_atomicity_20261009/README.md)은 이 구분의
공학적 사례다. CID만 비교하는 쓰기 조건은 오래된 요청과 일치했고 revision을 함께 비교하면
거부됐다. 이 관측은 철학적 시간론 전체의 증명이 아니라 구분이 필요한 한 반례다.

한 상태에서 여러 후속 상태를 탐색한 multiway 그래프는 **모형의 가능 경로**를 담는다.
그 모든 경로를 실행했거나 물리적으로 실재한다고 결론 내리지 않는다. 실행 사건 사이의
의존성과 벽시계 시간도 별도로 기록한다. 분산된 사건에 전역 총순서를 가정하려면 근거가 필요하다.

## 4. 관찰자와 Map

관찰자는 지정한 접근 범위에서 정보를 읽고, 어떤 규칙으로 그것을 해석하는 역할이다.
관찰자를 표현 안에 포함할 수 있어도 전체를 완전히 관찰한다는 뜻은 아니다.
HOH 화면, 문서, 파일 경로, 토큰 문맥은 모두 목적에 따른 표현이다.

층 사이 Map `M : S → T`를 쓸 때는 무엇을 보존해야 하는지 먼저 고른다. 예를 들어
관찰 `q`를 옮기려면 대상 층의 `q′`에 대해 `q = q′ ∘ M`을 요구할 수 있다.
`M(a)=M(b)`인데 `q(a)≠q(b)`라면 그러한 `q′`는 존재할 수 없다. 이 경우는 압축에서
필요한 정보를 버렸다는 반례다. 이 조건은 물리→뇌→의미의 실제 Map이 존재한다는 증명이 아니다.

대안은 정보를 더 보존하거나, 질의 범위를 좁히거나, 오차 한계를 선언하는 것이다.
왕복 가능한 Map과 요약·임베딩 같은 손실 변환을 구분한다. 모든 층의 Map이 가역적이라는
가정은 두지 않는다. 사용자 원칙 ①의 “최외각”은 관점으로 보존하고 절대적 외부 관찰자를
형식 이론에 무근거로 추가하지 않는다.

## 5. 인지와 프로그램

현재 사용자 정의는 CHU를 인지능력체라고 부르지만 **인지의 충분조건은 아직 명세하지 않았다**.
그래프를 저장하거나 정해진 규칙으로 바꾸는 것만으로 인지·이해·의식을 증명했다고 하지 않는다.
연구할 관측 항목으로는 상태/환경의 구별, 기억의 활용, 예측 또는 평가, 입력에 따른 행동,
오류에 따른 갱신을 제안한다. 이 목록은 모든 생물·우주·월드모델에 강제할 정의가 아니다.

프로그램은 실행 체계가 읽어 전이를 결정하는 구조라는 관점을 취한다. Semantic Weight의
수정이 행동을 바꾸려면 해당 구조를 읽는 인터프리터와 실행 의미가 필요하다. 데이터 이름에
“의미”가 있다고 해서 스스로 실행되지는 않는다. LLM=ROM은 동결된 실행 단위에 대한 사용자
비유이며 실제 반도체 ROM이나 오류 없는 연산자라는 동일성 주장이 아니다.

HSWM은 기존 사용자 범위에서 LLM 전용 경로다. 비-LLM 월드모델도 CHU 연구에 포함되므로
CHU의 일반 정의를 특정 모델 API, 학습 방식, 저장 엔진에 종속시키지 않는다. CHU_OS의
HOH·OMC·HSWM 연계는 구현 책임이며 각 저장소의 정체성과 권한을 덮어쓰지 않는다.

## 6. 계산가능성과 비용

유한하게 표현한 상태와 실행 가능한 국소 규칙은 연구의 출발점이다. 그 사실만으로
무한 진화의 전역 성질, 모든 도달성 질의, 종료 여부를 판정하는 알고리즘이 생기지는 않는다.
“Computable”은 무엇을 입력으로 받고 어떤 답을 언제 산출하는지의 범위를 요구한다.
우주 전체나 Ruliad와의 동일성·비동일성을 이름이나 유한 데모만으로 확정하지 않는다.

최소 비용 원칙은 비용과 정확도를 정하면 비교 가능한 가설이 된다. 작업 집합 `Q`, 표현 `R`,
정확도 조건 `D_Q(R)≤ε`를 고정하고 저장·전송·질의·갱신·변환 비용을 비교한다.
역할을 보존하는 incidence graph도 n항 관계를 담을 수 있으므로 이항 그래프의 표현 불가능성을
전제하지 않는다. 작은 이항 질의만 있는 경우, 고차 관계가 많은 경우, 갱신이 잦은 경우의
순위가 달라질 수 있다. 물리적 작용 원리와 이 비용 함수가 같다는 증명은 없다.

## 7. 철학 v1의 완료 기준과 다음 순서

이번 v1은 주요 용어의 범위, 주장별 근거와 미해결 질문, 형식화의 반례, OS가 따라야 할
계약을 한 진입점에서 읽을 수 있게 하는 정리 작업이다. 정의의 궁극적 확정이나 새 공리의
사용자 승인 상태를 만들어내지 않는다. [주장 목록](CLAIMS.md)의 열린 질문은 열린 채 유지한다.

다음 순서는 인지의 사례/비사례 비교 → 지속성·분기 정책 → 관측 보존 Map → 비용 반례
연구다. OS는 [별도 저장소](https://github.com/gj3447/CHU_OS)에서 이 계약의 유한 구현을
검사한다. 저장소 생성·초기 이관과 외부 소비자 전환의 상태는
[분리 기록](../docs/CHU_CHU_OS_REPOSITORY_SPLIT.md)을 따른다.
